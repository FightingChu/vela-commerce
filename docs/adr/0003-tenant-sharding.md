# ADR-0003: 租户分片采用逻辑分片 + 双写迁移

状态: 已采纳(2025-09)
相关 flag: `tenant_sharding`(默认关)

## 背景

单库写入了,但直接按租户拆物理库的成本高,且租户数量还在变。

## 决策

1. 引入 16 个**逻辑分片**,`shard_of(tenant_id)` 哈希映射,规则永久稳定
2. 物理库与逻辑分片解耦,初期 N 个物理库承接 16 个逻辑分片
3. 迁移期双写:老库为准,新库追平后切读,观测两周再停老库写

## 后果

- `ShardRouter.route()` 在 flag 关闭时一律回主库,开关粒度是全局的
- 扩物理库 = 重映射逻辑分片,不涉及租户数据重哈希
- 代价:双写期间对账 job 要容忍两库小差异(见 inventory/reconcile)
