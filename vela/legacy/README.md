# vela/legacy -- v1 遗留代码(只读,冻结)

## 来历

这里是 2019 年第一版单体应用拆出来的 v1 老代码。当时团队三个人,单体叫
`vela-v1`,2021 年 11 月整体迁到 v2(v2 拆成了现在的 vela 包结构)。迁移时
发现一批模块在生产上还有零星引用——老报表脚本、财务对账、一个没人敢动的
客户同步 crontab——不敢直接删,就整体搬进 `vela/legacy/` 冻结。

## 红线

1. **禁止新增需求。** 这里只允许语法级别的维护(保证能 import、不报错),
   任何新功能一律去 v2 实现。
2. **禁止 import 进新代码。** v2 代码(vela 包内除 legacy 外的所有目录)
   不允许 import 这里的任何模块。CI 没拦,靠 review,发现一律打回。
3. **别"顺手重构"。** 这里的代码风格就是历史,重构成"好看的代码"会破坏
   行为对照价值(v2 回溯 2019-2021 数据时靠它还原当时的处理逻辑)。

## 目录内容

| 文件 | 说明 | 现状 |
| --- | --- | --- |
| sms_v1.py | 旧短信网关封装,网关 2020-08 已下线,只会打日志返回 None | 死代码 |
| order_export_v1.py | 老订单 CSV 导出,财务 monthly_report.py 还在用 | 有引用 |
| promo_csv_v1.py | 促销码 CSV 导入,运营每年大促翻出来跑一次 | 有引用 |
| compat_dict.py | v1 API camelCase / v2 snake_case 字典互转,等 v2 网关收口后可删 | 有引用 |
| http_v1.py | urllib 老客户端,老对账脚本在用 | 有引用 |
| constants_v1.py | v1 常量(状态映射、费率),老报表依赖,2022-01 误删过一次引发对账事故 | 有引用 |
| currency_v1.py | 硬编码汇率表,2023-01 冻结停更,只服务历史区间换算 | 死代码 |
| customer_sync_v1.py | 客户同步老入口,输入路径早已不存在,留作行为参考 | 死代码 |

## 下线计划

整体下线依赖审计 retention 评审,工单 **#VT-1503**。评审要回答:
- 上述"有引用"模块的老脚本何时迁 v2;
- 2021 年以前的订单/客户数据要保留多久(决定 constants_v1、currency_v1、
  customer_sync_v1 的保留期);
- 合规侧对历史接口字段(compat_dict 映射表)有没有取证要求。

评审出结论之前,这个目录一个文件都不能动(2022-01 的对账事故就是结论
之前有人手痒删常量导致的)。
